# How it works

Every night (`KIA_RUN_AT`), kia runs four steps. You can also run them by hand, e.g. `docker compose exec kia python3 -m kia check`.

## 1. Check streams (`kia check`)

Every stream in your playlists is opened with `ffprobe`. A TV stream counts as working if it opens and has video; a radio station needs only audio. Some servers turn away anything that isn't a media player, or more than a couple of connections from one place, so kia introduces itself as VLC (the player most widely accepted) and tests at most two streams per server at a time. Streams that fail a name lookup or time out get a second, slower try before they count as failed. Only network addresses (`http`, `https`, `rtmp`, `rtsp`) are tested; anything else in a playlist, such as a file on this computer, is marked dead. Each stream is marked:

- ok: works now.
- flaky: failed tonight but worked before, and hasn't failed more than `grace_failures` nights in a row. It stays in the list, because free streams often drop out for a while.
- dead: everything else.

Channels listed more than once (same `tvg-id`) are reduced to the best stream: working beats flaky, then higher resolution, then faster response. Each channel kept gets a number (`tvg-chno`) the first time and keeps it, so numbers don't shift when other channels come and go. The result is `curated.m3u`. `report.html` shows the counts, common failures, and every channel kept.

### Radio

Lines starting with `radio-browser:` in `sources.txt` ask [radio-browser.info](https://www.radio-browser.info), a free community directory, for its most popular working stations that match your choices, such as a country, genre, language, or station name. Stations listed more than once are merged, keeping the best stream. They're tested like TV channels and marked as radio in the playlist, so Kodi shows them under Radio. Almost no radio station has guide data, so they get no placeholder blocks unless you turn on `KIA_RADIO_PLACEHOLDERS`.

## 2. Match channels to guide sources (`kia map`)

Kodi connects a channel to its guide by ID. Playlists from iptv-org use IDs like `CNN.us@East`; guide sites use their own. [iptv-org/epg](https://github.com/iptv-org/epg) keeps a table linking the two for thousands of channels. kia looks up each working channel in it (same feed first, then other feeds of the same channel), skips sites marked broken, and keeps up to three candidate sites per channel. `mapping-report.html` lists matched and unmatched channels.

This is also why guides built by hand are often nearly empty: the channel lists generated by iptv-org/epg's tools leave the ID blank, so nothing matches.

## 3. Download guide data (`kia grab`)

kia first updates its copy of iptv-org/epg to the latest version (or the one you've pinned; see [versions](configuration.md#versions)). If GitHub can't be reached, it uses the copy it has. For each candidate site, kia runs iptv-org/epg's downloader, a few sites at a time. If a site fails, its previous data is kept. i.mjh.nz (Pluto TV, Plex, Samsung TV Plus, Roku) publishes complete guide files, so kia reads those directly. That takes seconds and about 40 MB of memory, instead of about 25 minutes and over 2 GB.

## 4. Build the guide (`kia guide`)

For each channel, kia picks the site with the most programs in the next 24 hours and writes `guide.xml` and `guide.xml.gz`. A site with nothing in the next 24 hours (only old listings, for example) doesn't count. Channels with no data get blocks showing the channel's name (`placeholders`). A damaged guide file is skipped, and the other sites are still used. `guide-report.html` shows coverage by channel and site.

With an upstream server (`KIA_UPSTREAM_URL`), kia skips steps 2 and 3: it downloads the upstream's guide and keeps the channels in its own list. If the upstream can't be reached, it falls back to steps 2 and 3 (or the last copy, with `KIA_UPSTREAM_FALLBACK=cached`).

## The status page

`http://<your address>:8780/` shows how kia is doing: the last refresh and whether it worked, the next one, how many channels it found, the alerts from the last run, and links to the playlist, the guide, the reports, and these docs. kia updates it when a run starts and when it ends.

![kia's status page: the last refresh worked, the next is at 04:00, with channel counts, file links, and help links](../images/kia-status-screenshot.png)

| Status | Meaning |
|---|---|
| Refreshing now | A run is going. The counts are from the last run until it finishes. |
| Last refresh worked | Nothing needs you. |
| Last refresh worked, with alerts | The playlist and guide were updated, but something needs a look. The alerts are listed below the table; [troubleshooting](troubleshooting.md#alerts) says what to do about each. |
| Last refresh failed | The playlist or guide may not have been updated. See [the refresh failed](troubleshooting.md#the-status-page-says-the-refresh-failed). |
| Not run yet | kia's first run hasn't finished. It can take up to an hour. |

### `status.json`

The same information, for scripts and monitoring tools such as Uptime Kuma or Home Assistant, is at `http://<your address>:8780/status.json`:

| Field | Contents |
|---|---|
| `result` | `running`, `ok`, `alerts`, `failed`, or `never` |
| `last_run` | `started` and `finished` (UTC times), `minutes`, and `exit_code` (0 worked, 3 worked with alerts, anything else failed) |
| `next_run` | The next refresh, in local time with its UTC offset |
| `channels` | `tv`, `radio`, and `with_guide` (channels with guide data) |
| `alerts` | The last run's alerts: `time`, `event` (see [alerts](alerts.md)), and `title` |
| `playlist_url` | The playlist address for Kodi |
| `files` | The files in the output folder |
| `version` | kia's version |

A monitor should warn you when `result` is `failed`, and when `last_run.finished` is more than a day old, which means kia stopped running. For example, as a shell check that fails in either case:

```sh
curl -s http://192.168.1.20:8780/status.json | python3 -c '
import json, sys
from datetime import datetime, timedelta, timezone
s = json.load(sys.stdin)
done = s["last_run"]["finished"]
stale = not done or datetime.now(timezone.utc) - datetime.fromisoformat(done) > timedelta(hours=26)
sys.exit(1 if s["result"] == "failed" or (stale and s["result"] != "running") else 0)'
```

## DNS checks and alerts

When a stream or guide site's name can't be looked up, kia asks public DNS servers (`[dns] verify_resolvers`) as well. If they can't find it either, the stream or site is gone, and kia just reports it. If they can, your network's DNS is the problem (an ad-blocker or the router, for example), and since that would affect Kodi too, kia raises an alert. Names are tried twice on your network first, so a single slow lookup doesn't raise one. Some sites' own DNS servers send broken IPv6 answers, which make the lookup fail everywhere; kia recognizes that and reports it as the site's problem, not yours.

Alerts also cover a failed nightly run, sharp drops in working channels or guide coverage, and a guide site that keeps failing. They can go to your phone through ntfy or to any command you choose: see [alerts](alerts.md).

## Files

| Folder | Contents |
|---|---|
| `output/` | What gets served: the playlist, guide, reports (each as `.html` for browsers and `.md`), and the status page (`index.html`, with the same information in `status.json` for scripts) |
| `state/` | Stream history and the alert log |
| `work/` | Intermediate files: per-site channel lists, downloaded guides, logs |
| `vendor/epg/` | kia's copy of iptv-org/epg, updated nightly |

Deleting `work/` or `vendor/` is safe; they're rebuilt on the next run. Deleting `state/` resets stream history.
